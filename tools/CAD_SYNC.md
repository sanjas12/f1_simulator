# FreeCAD → Godot

## Как пользоваться

1. Откройте `assets/cad/prototype_02/Formula_Prototype_02.FCStd` в FreeCAD.
2. Откройте проект `formula_simulator/project.godot` в Godot 4.7.2.
3. Измените деталь в FreeCAD, например Position в Placement у антикрыла, и сохраните Ctrl+S в тот же FCStd.
4. Через несколько секунд в Output Godot появится `FreeCAD Sync: model updated`. Вернитесь в окно Godot, если оно было неактивным, и дождитесь переимпорта.
5. Запустите F5. Если заезд уже шёл, остановите его и запустите заново. Управление — WASD.

Первое открытие редактора также запускает экспорт. Для ручного повтора используйте Project → Tools → Update FreeCAD model. Плагин включён в Project Settings → Plugins. Путь к Python задаётся в Project Settings (Advanced Settings) → freecad_sync/python_executable; нужен именно `python.exe` из FreeCAD, сейчас `C:/Program Files/FreeCAD 1.1/bin/python.exe`.

## Что происходит

FCStd хранит CAD-тела. Экспортёр читает сохранённый документ и разбивает поверхности на треугольники (тесселяция), затем записывает самодостаточный glTF. Godot импортирует его как дочернюю сцену `FormulaCarMockup/Visual`. Все 44 детали сохранены отдельными узлами. Управляющий скрипт и камера находятся выше визуальной модели и не перезаписываются при экспорте.

Координаты переводятся из миллиметров в метры: `(x, y, z)` FreeCAD → `(-y, z, x − 2250) / 1000` Godot. Поэтому нос смотрит вдоль −Z, верх — +Y, а колёса касаются плоскости Y=0. Центр привязки фиксирован; при изменении длины он не смещается автоматически.

Обновляется геометрия деталей и их обычный Placement. Палитра пока задаётся в экспортёре по именам деталей: изменения цвета и видимости в FreeCAD не переносятся. Экспортируются все непустые Shape-объекты, поэтому не храните промежуточные тела рядом с финальными: они тоже попадут в игру. Иерархические сборки и App::Link пока не поддерживаются. Модель не содержит физической подвески, а колёса пока не вращаются. Коллизии и физические параметры нужно настраивать отдельно.

Таблица Dimensions в текущем FCStd справочная: её редактирование не меняет форму. Для перестроения макета используйте `build.FCMacro`, но он заменяет исходный FCStd и может затереть ручные правки — сохраняйте их копию заранее.

## Сбои и проверка

Экспорт работает в отдельном процессе и не блокирует редактор. Проверяются два последовательных одинаковых хеша исходника. Готовый glTF заменяется только после успешного экспорта. При ошибке сохраняется предыдущая модель; подробности находятся в `formula_simulator/.godot/freecad_sync.json`. Исправьте исходник и сохраните его снова либо вызовите ручное обновление. Несохранённые изменения не отслеживаются. При закрытом Godot никакой наблюдатель не работает.

Ручной экспорт из PowerShell в корне репозитория:

```powershell
& 'C:\Program Files\FreeCAD 1.1\bin\python.exe' tools/export_freecad.py
```

Проверка интеграции (подставьте путь к Godot):

```powershell
& 'путь\Godot_v4.7.2-stable_win64_console.exe' --headless --path formula_simulator --script ../tools/check_cad_scene.gd
```

Проверены импорт 44 деталей, габариты 1,8 × 0,95 × 4,5 м, контакт с плоскостью, движение вперёд и запуск автоматического экспорта из редактора. Текущая сетка: 17 296 треугольников. Тест габаритов рассчитан на текущий макет; после намеренного изменения размеров обновите ожидаемые значения.

Изучено: отличие CAD-тела от игровой сетки, преобразование осей и единиц измерения, отдельная визуальная сцена и автоматический переимпорт ресурсов. Механизм использует [EditorPlugin Godot](https://docs.godotengine.org/en/4.5/classes/class_editorplugin.html).
