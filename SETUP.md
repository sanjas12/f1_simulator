# Подготовка окружения на Windows

Этот этап выполняется **до написания игрового кода**. Его результат — установленный Godot, созданный пустой проект и понимание того, зачем нужен каждый инструмент.

## 1. Что уже есть на компьютере

Проверено 26 августа 2026 года:

| Инструмент | Состояние | Примечание |
| --- | --- | --- |
| Git | Установлен | `git version 2.54.0.windows.1` |
| Visual Studio Code | Установлен | Версия `1.134.0`, x64 |
| Godot | Не найден | Требуется для первого этапа |
| Python | Не установлен | Есть Windows launcher `py`, но нет интерпретатора |
| Blender | Не найден | Понадобится позже для 3D-моделей |
| WinGet | Не найден | Поэтому ниже описана ручная установка |

На диске `D:` свободно примерно 2,9 ГБ. Godot поместится, однако перед установкой Blender и добавлением ассетов рекомендуется освободить **не менее 10 ГБ**.

## 2. Установить Godot

Для проекта нужна **стандартная x86_64-версия Godot 4.7.2**, а не вариант `.NET`:

1. Открыть [официальную страницу Godot для Windows](https://godotengine.org/download/windows/).
2. Скачать **Godot Engine 4.7.2 — Windows x86_64**.
3. Не выбирать `.NET`: он предназначен для C#, а мы начинаем с GDScript.
4. Распаковать архив, например, в `C:\Tools\Godot\4.7.2\`.
5. Запустить файл `Godot_v4.7.2-stable_win64.exe`.
6. При желании создать ярлык на рабочем столе.

Godot является переносимой программой: отдельный установщик не нужен. Пока не скачивайте export templates — они понадобятся только тогда, когда мы начнём собирать самостоятельный `.exe`.

### Зачем фиксировать версию

Все участники и все проверки проекта должны использовать одну версию движка. Это снижает вероятность неожиданных изменений физики, формата сцен и импорта ресурсов. Обновляться будем осознанно, отдельным шагом и через Git.

## 3. Первый запуск Godot

1. Открыть Godot Project Manager.
2. Выбрать **Create**.
3. Название проекта: `Formula Simulator`.
4. Папка: `D:\My_work\F1 - симулятор`.
5. Для начала выбрать renderer **Forward+**.
6. Не включать создание отдельного Git-репозитория: текущая папка уже находится под контролем Git.
7. Нажать **Create & Edit**.

Если Godot сообщает о проблемах с Vulkan или редактор отображается некорректно, создать проект с renderer **Compatibility**. Это не меняет нашу архитектуру и подходит для учебного прототипа на более старой видеокарте.

После создания в корне должны появиться как минимум `project.godot` и папка `.godot`. Папка `.godot` содержит локальный кэш и не должна попадать в Git.

## 4. Проверить Godot

В редакторе:

1. Открыть меню **Help → About Godot** и убедиться, что указана версия `4.7.2 stable`.
2. Создать временную сцену с корневым узлом `Node3D`.
3. Сохранить её как `scenes/main.tscn`.
4. Нажать `F6` и убедиться, что пустая сцена запускается без ошибки.
5. Назначить её главной сценой, когда Godot предложит это сделать.

Пустое серое окно на этой проверке — нормальный результат: мы проверяем работу движка, а не графику.

## 5. Редактор кода

На первом этапе рекомендуется встроенный редактор Godot:

- он показывает документацию по API по клавише `F1`;
- знает сцены, узлы, сигналы и свойства Godot;
- не требует расширений;
- позволяет сосредоточиться на GDScript, не на настройке инструментов.

VS Code уже установлен, но подключать его будем позже, если встроенного редактора станет недостаточно. Это также позволит на практике понять, какие возможности IDE действительно нужны.

## 6. Python и Blender — не обязательны прямо сейчас

Чтобы не перегружать первый этап, их можно установить перед соответствующими задачами.

### Python

Python понадобится для анализа CSV-телеметрии. Когда дойдём до телеметрии:

1. Скачать актуальный Python 3.14 x64 с [официальной страницы Python для Windows](https://www.python.org/downloads/windows/).
2. Установить интерпретатор для текущего пользователя.
3. Проверить в новом PowerShell: `py -V`.
4. Для зависимостей проекта использовать отдельное виртуальное окружение, а не глобальную установку пакетов.

GDScript исполняется внутри Godot и **не требует установки Python**.

### Blender

Blender понадобится после серого прототипа. Рекомендуемая стабильная ветка — [Blender 5.2 LTS](https://www.blender.org/download/lts/), поддерживаемая до июля 2028 года. Пока трассу и машину будем собирать из простых примитивов Godot: это позволит проверять физику независимо от графики.

## 7. Git перед началом работы

Git уже установлен. После создания проекта нужно проверить:

```powershell
git status
```

До первого коммита необходимо добавить `.gitignore`, исключающий как минимум:

```gitignore
.godot/
```

Кэш `.godot` генерируется заново движком. Файл `project.godot`, сцены, скрипты и исходные ассеты, напротив, должны храниться в Git.

## 8. Критерии завершения этапа

Окружение готово, когда выполнены все пункты:

- [ ] На диске достаточно места для проекта и кэшей.
- [ ] Запускается стандартный Godot 4.7.2 x86_64.
- [ ] Проект открывается из `D:\My_work\F1 - симулятор`.
- [ ] Выбран Forward+ либо Compatibility при проблемах с Vulkan.
- [ ] Пустая `Node3D`-сцена запускается без ошибок.
- [ ] В корне появился `project.godot`.
- [ ] `.godot/` исключена из Git.
- [ ] Команда `git status` выполняется без ошибки.

После этого можно переходить к первому учебному прототипу: сцена, свет, камера, поверхность трассы и неподвижный корпус машины.

## Что важно понять на этом этапе

- Godot — это движок и редактор, GDScript — язык игровой логики.
- Сцена является сохраняемым деревом узлов, а не просто «уровнем».
- `project.godot` хранит настройки проекта, а `.godot/` — локальный кэш.
- Renderer влияет на вывод графики, но не определяет архитектуру физической модели.
- Git хранит исходники проекта; сгенерированные кэши в него не добавляются.
