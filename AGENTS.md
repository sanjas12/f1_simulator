# AGENTS.md

## Цель проекта

Учебный хардкорный 3D-симулятор автомобиля класса Formula. Пользователь знает Python и осваивает Godot, GDScript, игровую архитектуру и физику автомобиля в процессе разработки.

## Главный приоритет

Проект должен не только работать, но и помогать учиться:

- объяснять новые понятия простым языком;
- двигаться небольшими проверяемыми шагами;
- не скрывать важную логику за чрезмерными абстракциями;
- комментировать причины технических решений, а не каждую строку кода;
- после каждого этапа указывать, что было изучено и как проверить результат самостоятельно.

## Технологии

- Godot 4.7.2 Standard x86_64.
- Типизированный GDScript — основная игровая логика.
- `RigidBody3D` и собственные подсистемы физики вместо `VehicleBody3D` как финальной основы.
- Python — будущий анализ CSV-телеметрии, не игровая логика.
- Blender 5.2 LTS — будущие 3D-модели; сначала использовать примитивы Godot.
- Windows — единственная целевая платформа первой версии.

## Текущий этап

Подготовка окружения завершена по `SETUP.md`. Есть кинематический прототип с вводом WASD. Внешний вид подключён из FreeCAD через `tools/export_freecad.py` и редакторский плагин `formula_simulator/addons/freecad_sync/`. Правила и ограничения экспорта — в `tools/CAD_SYNC.md`. Python встроен в FreeCAD и используется только как инструмент подготовки ассетов.

Не создавать физику автомобиля, трассу или игровые системы, пока не подтверждено, что:

- Godot 4.7.2 запускается;
- проект открывается из текущей папки;
- пустая `Node3D`-сцена запускается без ошибок;
- создан `project.godot`;
- `.godot/` исключена из Git.

## Первая версия

- Одна вымышленная Formula-машина.
- Одна тестовая трасса.
- Режим хотлапа без ИИ и сетевой игры.
- Клавиатура и геймпад; руль и force feedback — после выбора устройства.
- HUD, чекпоинты, таймер круга и CSV-телеметрия.

## Правила работы

- Перед изменениями читать `README.md`, `PLAN.md` и относящийся к этапу документ.
- Не обновлять версию Godot без отдельного решения и проверки совместимости.
- Не добавлять платные зависимости и лицензированный контент Формулы 1.
- Отделять ввод от физической модели автомобиля.
- Держать шины, подвеску, тормоза, двигатель, коробку и аэродинамику независимыми подсистемами.
- Использовать фиксированный физический шаг и стремиться к воспроизводимым результатам.
- Сначала проверять механику на простых формах, затем улучшать графику.
- Не добавлять зависимость, пока её назначение нельзя объяснить в одном коротком абзаце.
- После значимого этапа обновлять `README.md`, а при изменении направления — `PLAN.md` и этот файл.

## Проверка изменений

- Запускать проект и проверять вывод Godot на ошибки и предупреждения.
- Проверять `git diff --check`.
- Не добавлять в Git `.godot/`, временные файлы, сборки и экспортированную телеметрию.
- Для физики добавлять наблюдаемую проверку: диагностические значения, визуализацию сил или телеметрию.
